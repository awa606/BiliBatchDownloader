# 0.3.0 VERIFY r3：实况空正文兼容与选组复验

2026-10-17，起始提交2e86ea0。当前已通过用户体验验收的版本仍为0.2.0；本轮修复BUG-009，不改变布局、数据库、身份或联网限额。

## 原因与最小修复

r2实际失败字段是实况段落的`text:null`。正式gallery-dl 1.32.16提取器遇到该段落后继续提取后续段落，本地原先强制要求对象，导致提前拒绝。安装源码已与PyPI wheel和sdist逐字节核对，见[来源收据](gallery-dl-1.32.16来源核验.json)。本轮沿用该发行包，不升级、不新增第二套请求实现。

修复只允许明确缺失或NULL的可选text，不将false、数字、字符串、数组或损坏nodes当作空正文。普通文字和富文本仍独立保留，按原段落组织纯文本。为避免适配器遗漏，上游同次解析产生的content片段与本地片段逐一比较，内容、数量、顺序任一差异都在媒体派发前停止；持久证据只有计数和SHA-256，没有正文。此对照证明与该固定提取器一致，不代表识别所有未来未知正文形式。

修复前最小用例1 FAIL：含NULL的图片/独立段落前后有文字时，上游PASS而本地REJECTED；证据`.artifacts/r3-before-fix.xml`保留。修复后定向106 PASS；包含缺失/NULL、相邻段落、中文/换行/空格、word/rich共存、非空异常拒绝、原生片段遗漏/改写/换序/重复及日志脱敏。

## 本轮执行顺序与预算

先完成全量回归、真实FFmpeg合成实况、编译/依赖检查和新冻结程序检查，再登记独立实验。`gallery_product_verify.py --sample livephoto`仅允许以下两个固定阶段；注册后改变模式、选择或预算会在worker启动前拒绝。

| 阶段 | 固定样本/选择 | 请求上限 |
|---|---|---:|
| 实况准备 | 1257912749013336118，UID 1337856191，9张照片预览 | 11 |
| 所选实况下载 | 第1、5、9组，图片复用缓存，只请求对应MP4 | 5 |

合计最多16次；零重试、零跳转、开始间隔至少1秒，每阶段180秒/网络等待15秒，页面原始和解码后各3MiB、单资产64MiB、跨阶段媒体256MiB。已有基线SHA `a98aaf48db64d4c85bc5baeaf7ccc59a0c609d699d60b34cdcc345ded8dd3b5b`不可替换。首个失败停止全部后续阶段；不刷新浏览器、不重跑四图、不换入口或账号补跑。

真实正文只进入新实验私有库，公开记录为状态、长度、片段数和哈希。准备成功不代表已归档；仅第1/5/9组成组保存才为所选完成，整篇仍为3/9组。实况MP4要求正时长、完整解码及至少2帧，未选MP4不请求。
