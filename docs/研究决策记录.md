# RDR-001 作者作品库候选与证据

## 问题、约束与边界

目标是中文Windows作者作品库：关注/手动作者 → 作者作品 → 详情预览 → 按需下载 → 本地打开。必须覆盖普通投稿、多P、动态多图、实况/动画、独立动态视频和转发，不能只按投稿列表建库。

分类要求已确认：作者内按图文／图片、投稿视频、动态视频及待分类管理，界面与新下载目录一致；旧文件原位保留。作品展示类别、发现入口、发布/转发记录与底层资源身份分别保存，不能用扩展名或BV存在与否替代原站分类依据。实况照片的配套MP4属于图文／图片资产，同BV/CID的投稿与动态引用共享资源。

用户批准新增独立工程与公开仓库；旧工具、原素材和入口保留。关注同步由用户触发，不自动下载关注者全部作品。凭据、名单、数据库和私人媒体不公开。关键研究通过后再完成设计评审，才能进入业务编码。

## 未选择的替代方案与风险

- 全盘复制原工具不能补齐作品库、稳定身份和动态完整性，也会保留旧问题。
- 直接复制PixivDesk会带入平台协议假设，且其VERIFY状态不能成为本工具验收。
- gallery-dl单独承担全部动态索引会遗漏非opus类型；必须独立验证。
- 未研究的自建下载器不能因为上游一次失败就被视为正确选择。
- 最大未决风险是平台接口可用性、类型/分页完整性、工作进程终止以及实际分发许可。
