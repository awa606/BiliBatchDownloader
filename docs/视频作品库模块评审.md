## DESIGN REVIEW

| 项目 | 本次决策 |
|---|---|
| Goal | 用户能实际浏览已验证视频作者/作品/分P/预览并本地播放；独立原生视频实验成功后开放联网任务 |
| Deliverables/PBS | 作品库及查询服务；QML桌面；持久化队列/worker；原生下载候选；便携包、手册、测试及证据 |
| Input/Output | 已授权本地报告与原位文件、用户BV/分P、本人专用Chrome档案 → SQLite元数据、任务事件、新下载文件；公开仅代码/合成测试/脱敏结论 |
| Constraints | Python3.13；独立用户数据；不读旧素材目录；不改旧工具；图片实验停止；研究12请求/230秒/64MiB/零重试 |
| Largest uncertainty | 上游原生网络及稳定身份是否可在预算内完成；在线失败不阻塞离线作品库发布候选 |
| Architecture | QML → Bridge/后台查询 → SQLite；队列 → 私有Windows Job子进程 → yt-dlp原生流水线 → 核验 → 原子发布 → SQLite |
| Modules/data ownership | library拥有schema与事务；bridge拥有导航/查询请求序号；worker拥有耗时IO；native拥有上游参数及白名单元数据映射；process拥有生命周期；settings仅本地路径 |
| Interfaces | query(filter,offset,limit≤40)→JSON快照；run(action,payload)→JSONL phase/progress/result/error；open(asset)→缺失提示或默认程序；失败只固定类别，原异常与地址不传出 |
| WBS | M1离线模型/原位登记→M2界面与浏览→M3队列及原生候选→M4回归/实测→M5便携包/维护；负责人Codex，用户负责真实体验验收；证据集中本次交付报告 |
| Dependencies/critical path | M1→M2→M4→M5为离线交付链，M3单独实验通过后进入联网可用分支；无日历排程数据，不编造CPM工期 |
| Risks | 平台阻断→立即停止；退出留下进程→Job关闭杀树；重复文件→BV/CID唯一约束+无覆盖发布；路径丢失→本地打开前后台核验；许可→外置动态库/许可清单；5000条性能→分页实测；范围扩张→后续需求保留矩阵 |
| Validation | SQLite去重/重启状态/缺失文件；真实worker取消；Qt加载/两尺寸和缩放；原生预算/重定向/GZIP离线对照；固定一次线上；冻结包实际启动 |
| Milestones | M-offline=VERIFY可运行库；M-native=仅固定样本PASS；全产品门禁独立，干净Windows和用户体验未验不记DONE |

五问：按数据/界面/网络进程边界拆分以避免冻结和误归档；替代是继续扩旧UI或新Web栈，均无已有Qt资产优势；最可能失败为原生在线/退出恢复；先隔离Spike，再一次真实请求；由实际EXE、数据库行为、测试/CI与用户体验分别证明交付。
